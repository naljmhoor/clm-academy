# Ask CLM — connecting a real AI service

The shipped build runs Ask CLM in **knowledge-search mode**. Answers come from the CLM knowledge base (`src/training/knowledge/articles.ts`) and from the current simulated case (`evaluateRequirements`), and the panel labels them as "not generated by AI". Nothing is sent anywhere.

To use a language model, deploy a small server endpoint. API keys must stay on the server and never go into the frontend bundle.

## 1. Frontend switch

Build with the endpoint URL:

```bash
VITE_ASSISTANT_ENDPOINT=https://<your-host>/assistant/answer npm run build
```

`src/training/assistant/client.ts` then POSTs every question to that URL. If the call fails, the panel falls back to knowledge search and says so.

## 2. Request (from the browser)

```json
{
  "question": "Why can't I approve this case?",
  "locale": "en",
  "context": {
    "module": "case-workspace",
    "caseId": "CS-1845",
    "tab": "overview",
    "caseStatus": "in_progress",
    "incompleteItems": ["National Address", "Signing Authority"]
  },
  "knowledgeIds": ["clm-overview", "case-intake", "..."]
}
```

The request contains no client names, national IDs, CR numbers or other personal data. Only the requirement labels of the simulated case are sent.

## 3. Response (from the server)

```json
{
  "answer": "string",
  "points": ["optional bullet", "..."],
  "status": "answered | not_found | unverified",
  "citations": [{ "articleId": "closing", "title": "Why is approval blocked?", "sources": ["CLM BRD Phase I — UC013 ..."] }],
  "actions": [{ "label": "Go to National Address", "route": "/cases/CS-1845?tab=overview&focus=address" }]
}
```

## 4. Server responsibilities

1. Retrieve passages only from approved sources: the BRD, approved use cases, the user manual, FAQs, release notes and documented procedures. Keep the article ids above as stable citation keys.
2. Ground the model on the retrieved passages and the `context` block. Instruct it to answer `not_found` when the passages don't cover the question, and to mark proposed or future rules as `unverified`.
3. Reply in the language of the question (`locale`).
4. Never forward identifiers or personal data. Log questions only under Manafa's data-handling policy (SAMA / PDPL).
5. Keep the model key in a server-side secret store. Rate-limit and authenticate the endpoint.

Because this build has no server, the model call is not implemented. Treat this capability as **requires external integration**.
